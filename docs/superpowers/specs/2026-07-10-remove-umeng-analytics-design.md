# 移除友盟统计与自动更新检查

## 目标

构建一个加强隐私保护的 SmsForwarder 版本：不打包或初始化友盟统计，并且不在应用启动时自动访问项目的更新服务。

## 范围

### 移除友盟

- 从应用模块中删除全部 `com.umeng.umsdk` 依赖。
- 删除 `APP_ID_UMENG` 构建配置字段及其后备 AppKey。
- 删除友盟初始化类及应用启动时的调用入口。
- 删除 Fragment 基类中的友盟页面访问统计调用。
- 删除友盟专用的 ProGuard 规则。
- 更新仓库文档和应用内置隐私说明，不再声明应用集成友盟或在启动时向友盟发送信息。

### 移除自动更新检查

- 删除主界面启动时自动触发的更新检查。
- 删除自动更新偏好项、常量和设置开关，避免旧版本保存的偏好值重新启用后台更新检查。
- 保留“关于”页面中由用户主动触发的手动更新检查。

## 不在本次范围内

- 不修改用户主动配置的任何转发渠道。
- 不删除手动更新检查。
- 不修改 FRPC 及其由用户主动触发的动态库下载行为。
- 不进行全局网络封锁，因为 SmsForwarder 的用户自定义转发渠道需要使用网络。

## 调整后的数据流

应用启动时只执行本地初始化，不初始化任何统计 SDK，也不调用项目更新接口。只有在用户配置了转发渠道、手动检查更新，或主动使用其他依赖网络的功能时，应用才会按对应功能发起网络请求。

## 验证方式

- 扫描受 Git 管理的源码和配置文件，检查友盟包名、AppKey、初始化调用、页面统计调用及自动更新标识符是否仍有残留。
- 检查应用依赖树，确认不存在友盟组件。
- 构建调试版 APK，验证源码编译、资源处理、代码压缩和打包流程正常完成。
- 确认“关于”页面仍保留手动更新功能，并且不再显示自动更新开关。

本次改动以删除依赖、配置和代码为主，因此不为已删除的代码新增单元测试，而是通过源码扫描、依赖检查和完整应用构建进行验证。

## 验收标准

- 生成的 APK 不包含友盟 SDK 依赖或友盟业务代码。
- 打开或恢复应用时不会自动发起更新请求。
- 手动更新检查和用户配置的转发功能仍能正常编译并保持可用。
